# Feasibility and Round 2 plan

After concept selection, size the MVP around one end-to-end workflow. Record the frontend, backend, model, state store, data, APIs, deployment, owners and integration order. Classify each component as essential, high-value enhancement, stretch or future scope. For dependencies, check access, costs, license, reliability and fallback. Favor a demonstrable path using confirmed resources.

Once shortlisted and permitted to build, assign the critical path and agree on a freeze time by working backward from the confirmed deadline. Build and integrate the core first, test expected and failure cases, then rehearse the live demo. Keep a local or prerecorded fallback where permitted and label any simulated data or recorded output. Track team contributions and third-party dependencies as work proceeds.
